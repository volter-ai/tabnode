# tabnode — rules for the agent working this repository

## Main and publication (owner rule, 2026-10-14)

Main is autonomous integration. Never ask the owner for permission to work, change policy, commit, push or merge to main. Main never publishes. Only publication may require user permission. Prepare an exact release source and request explicit publication authorization before creating or advancing the separate `publish` branch, dispatching publication, or publishing. A main merge never moves `publish`.

No CI tests or merge gates. Every retained CI workflow must finish within 60 seconds end to end, in every repository, with no exceptions. Job timeouts bound execution; a timeout, cancellation, skipped run or per-job shard budget does not establish successful completion within the ceiling. Do not run CI to validate this policy change.

- **What this is.** The Node engine of `volter-ai/browser-substrate`, a fork of `macaly/almostnode`. `CONSTITUTION.md` is what it must remain; `CONTRIBUTING.md`, `RELEASING.md` and `scripts/NODE-TESTS.md` are how a fix, a release and a measurement are done; `CLAUDE.md` is the tour of the tree.
- **A fix goes toward Node, at source.** It states which Node behaviour it restores, is general to every program, and never recognises a package, a project or a framework. A module of the engine's own exists only where Node's is native and the tab has no twin, with the reason at its site.
- **The engine never imitates a package.** A package that sits on a builtin is installed by the project and runs unchanged.
- **Git.** Fixes land on `main`; `dist/` is never committed. A release is cut the way `RELEASING.md` says: a tag `v<version>` on `publish`, which the `publish` workflow builds and publishes to npm as `@volter/tabnode` with provenance, and the substrate moves its pin to that version.
- **No gates.** No required checks, no merge gate. The remote `measure` workflow is retired. `publish` is the explicitly authorized release from the separate publication branch; it never gates a main merge. What is fast enough to check belongs in the committer's hands at the moment of the change.
- **No incidental testing during development.** Do not run tests, suites, typechecks, lints, probes, or reviews while building, locally or remotely. Moving a run to CI, GitHub Actions, another machine, or another agent does not make it allowed. This rule prevents time spent on verification that is not the task. When the user explicitly asks for a measurement, baseline, test harness, or capability ledger, implementing and running that measurement is the deliverable and is authorized; it is not an incidental development check. Run the requested measurement locally, report its exact scope and conditions, and do not add unrelated checks or subjective scores. Remote tests or measurements, especially GitHub Actions, require the user's explicit authorization for that remote run; a general measurement request is not remote authorization. Do not add automatic test or measurement triggers.
- **Do not edit** `LICENSE`, or the vendored files under `src/node-lib/`: a bug in one of those is fixed by moving to a newer Node, never by an edit.
